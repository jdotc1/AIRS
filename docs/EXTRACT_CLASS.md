# EXTR class boundary v51

Model `arm64-bounded-extract-class-v51` restricts extract-family entry to
`word & 0x7f800000 == 0x13800000`, replacing the mask `0x1f800000`.
Bits 30:29 must be `00` and bits 28:23 must be `100111`; bit 31 remains free.
Words outside this class continue through dispatch and report
`unsupported_instruction` instead of `invalid_extract_encoding`.

Inside the class, W EXTR retains form `0x13800000` with shifts 0–31 and X EXTR
retains form `0x93c00000` with shifts 0–63, under the form mask `0xffe00000`.
Register fields and immediate extraction are unchanged. W shifts 32–63 and the
six other class forms retain `invalid_extract_encoding`. The bitfield family
was deliberately left unchanged: its fourth opcode value was unallocated in
the supplied oracle, and no owned example showed otherwise.

## Bounded evidence

The independent extract-class tests cover valid W shifts 0 and 31, valid X shifts
0, 31, 32 and 63, and register-field extremes 0 and 31. Refusal controls cover
all six other class forms and W shifts 32 and 63. Outside-class controls include
the eight LLVM words, twelve free-field boundary words, and 2,000 pseudo-random
words with fixed seed 51. The tests also pin the current and historical identities.

Python and native registries include v51 and retain v50. Registry tests cover
label parity and every registered label's report admission and subtype refusal.
A native reuse control admits a current v51 report and refuses an unknown label
for current-model reuse, preserving generic saved-report wire import behavior.
The two producer-control fixtures were regenerated by their scripts; only the
model label changed.

Local source checks before publication: the extract-class file passed (7 tests),
the Python suite passed (3,087 tests, 18 skipped), and both native release
products built with no long type-check warning. The local native test run
executed 1,181 tests; its only failures were six path-comparison cases in the
bundle-discovery, private-runtime and portable-manifest tests, caused by the
checkout sitting below a symbolically linked folder. None of them reads the
analysis model. The repository workflow run for the pull request is the record
for the native suite.

## Limits

This change does not decode, model or support `autiasppc` or `autibsppc`.
A function containing either remains unresolved; only its reported reason changes.
It does not claim that every outside-class word is valid: the extract family
simply does not judge those words. No word outside the extract-family entry space
changes. The legacy decoder, bitfield handling, recovery scope, schema and
historical report identities are unchanged. No corpus qualification, application
interaction acceptance or distribution qualification is claimed.
